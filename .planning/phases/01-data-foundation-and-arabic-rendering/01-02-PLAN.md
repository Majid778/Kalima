<objective>
Build the complete data pipeline that processes raw Quran data from Tanzil.net and corpus.quran.com into a pre-populated SQLite database. The pipeline must: parse Tanzil XML for Arabic text, merge corpus morphological data (root, POS), compute frequency rankings, assign words to levels per level-config.json, link example verses, validate Tanzil checksums, log data gaps, and write the final kalima.db.

Purpose: The database is the foundation every feature screen depends on. Without verified, frequency-ranked vocabulary data, no learning, practice, or quiz feature can function.
Output: `assets/db/kalima.db` (pre-built database), `scripts/gaps-report.json` (gap audit), `scripts/validate-db.js` (validation script).
</objective>

    // scripts/build-db.js — Kalima Data Pipeline
    // Run: node scripts/build-db.js
    // Output: assets/db/kalima.db, scripts/gaps-report.json

    const Database = require('better-sqlite3');

    **Step-by-step pipeline logic:**

    a) **Parse Tanzil XML** using fast-xml-parser with `{ ignoreAttributes: false, attributeNamePrefix: '' }`. Extract all 6,236 ayahs across 114 surahs. Each ayah has `index` (number) and `text` (Arabic with tashkeel).

    b) **Tokenize ayahs** — split each ayah's text by whitespace to get individual word tokens. Count total occurrences of each unique lemma/word form across all 77,430+ tokens.

    c) **Load corpus morphology** — parse the CSV/TSV file to get root letters, part of speech, and lemma for each word position. Map by (surah, ayah, word_position) to match against Tanzil tokens.

    d) **Merge data sources** — for each unique lemma:
       - `arabic`: the word form with full tashkeel (from Tanzil)
       - `transliteration`: generate from Arabic text (use a transliteration mapping table: alif->a, ba->b, etc.) OR source from corpus data if available
       - `meaning`: English meaning from corpus or a bundled dictionary file
       - `root`: from corpus morphology (NULL if missing, per D-04)
       - `part_of_speech`: from corpus morphology (NULL if missing, per D-04)
       - `occurrence_count`: computed from Tanzil token frequency
       - `frequency_rank`: rank by occurrence_count descending (rank 1 = most frequent)

    e) **Assign words to levels** using level-config.json:
       - Sort words by frequency_rank ascending (most frequent first)
       - Distribute into 30 levels, each containing 25-50 words (from `wordsPerLevel` config)
       - Level 1 gets the top ~40 most frequent words, Level 2 gets the next ~40, etc.
       - For each level, compute `cumulative_coverage = sum(occurrence_count for words in levels 1..N) / total_token_count`
       - Store level `name` from level-config.json, `word_count`, and `cumulative_coverage`

    f) **Select example verses** for each word:
       - Find all ayahs containing the word
       - Select up to 3 example verses (prefer shorter ayahs for readability)
       - Store `surah_number`, `ayah_number`, full `arabic_text` of the ayah, `translation` (Sahih International), and `word_position` (token index)

    g) **Validate Tanzil checksums** — compare computed per-surah letter counts against Tanzil's published values. If any surah fails, throw an error with details. Log success/failure counts.

    h) **Generate gaps-report.json** per D-05:
       ```json
       {
         "generated": "ISO-8601-timestamp",
         "totalWords": 1450,
         "gapsCount": 87,
         "gaps": [
           {
             "wordId": 142,
             "arabic": "word",
             "frequencyRank": 15,
             "missingFields": ["root", "partOfSpeech"],
             "note": "auto-detected gap"
           }
         ]
       }
       ```
       Write to scripts/gaps-report.json. Log summary to console: "X words with gaps out of Y total".

    i) **Write kalima.db** — create the SQLite database at assets/db/kalima.db:
       - Create tables matching the schema in src/data/schema.ts (use CREATE TABLE IF NOT EXISTS)
       - Create indexes: idx_words_level, idx_words_frequency, idx_word_verses_word
       - Insert all data using transactions for performance (batch inserts of 500 rows)
       - Do NOT create word_progress or level_progress tables — those are user tables created by Drizzle migrations at runtime
       - Log final counts: "Wrote X words, Y levels, Z verses to kalima.db"

    j) **Error handling:**
       - If Tanzil XML file is missing, print clear error message with download instructions
       - If corpus morphology file is missing, warn but continue (all root/POS will be NULL)
       - If level-config.json is missing, abort with error
       - Wrap entire pipeline in try/catch, log errors with context

    **IMPORTANT NOTES:**
    - The transliteration and meaning fields are the hardest to source. If corpus.quran.com does not provide English meanings, consider bundling a supplementary dictionary file (e.g., from an open-source Quran dictionary project). The build script should document which sources it uses for each field.
    - The script runs in Node.js (not in the React Native app). Use CommonJS requires, not ES module imports.
    - Use better-sqlite3's synchronous API for all DB operations.
    - Use transactions for bulk inserts (`db.transaction(() => { ... })()`)

    1. Create scripts/validate-db.js — a standalone post-build validation script:
       ```javascript
       #!/usr/bin/env node
       // scripts/validate-db.js — Post-build database validation
       // Run: node scripts/validate-db.js
       // Exit code: 0 = valid, 1 = errors found

       const Database = require('better-sqlite3');
       const path = require('path');
       const fs = require('fs');

       const DB_PATH = path.join(__dirname, '..', 'assets', 'db', 'kalima.db');
       const GAPS_PATH = path.join(__dirname, 'gaps-report.json');

       let errors = 0;

       function check(name, condition, detail) {
         if (condition) {
           console.log(`  PASS: ${name}`);
         } else {
           console.error(`  FAIL: ${name} — ${detail}`);
           errors++;
         }
       }

       // Check 1: DB file exists and is not empty
       check('DB exists', fs.existsSync(DB_PATH), `${DB_PATH} not found`);
       const stats = fs.statSync(DB_PATH);
       check('DB size > 100KB', stats.size > 100 * 1024, `Size: ${stats.size} bytes`);

       const db = new Database(DB_PATH, { readonly: true });

       // Check 2: Table counts
       const wordCount = db.prepare('SELECT COUNT(*) as c FROM words').get().c;
       check('Words > 500', wordCount > 500, `Got ${wordCount}`);

       const levelCount = db.prepare('SELECT COUNT(*) as c FROM levels').get().c;
       check('Levels 25-35', levelCount >= 25 && levelCount <= 35, `Got ${levelCount}`);

       const verseCount = db.prepare('SELECT COUNT(*) as c FROM word_verses').get().c;
       check('Verses > 500', verseCount > 500, `Got ${verseCount}`);

       // Check 3: No empty string roots/POS (must be NULL per D-04)
       const emptyRoots = db.prepare("SELECT COUNT(*) as c FROM words WHERE root = ''").get().c;
       check('No empty root strings', emptyRoots === 0, `Found ${emptyRoots} empty root strings`);

       const emptyPOS = db.prepare("SELECT COUNT(*) as c FROM words WHERE part_of_speech = ''").get().c;
       check('No empty POS strings', emptyPOS === 0, `Found ${emptyPOS} empty POS strings`);

       // Check 4: Required fields not null
       const nullRequired = db.prepare(
         `SELECT COUNT(*) as c FROM words
          WHERE arabic IS NULL OR transliteration IS NULL OR meaning IS NULL
          OR frequency_rank IS NULL OR occurrence_count IS NULL`
       ).get().c;
       check('No null required fields', nullRequired === 0, `Found ${nullRequired} with null required fields`);

       // Check 5: Every word has at least 1 verse
       const orphanWords = db.prepare(
         `SELECT COUNT(*) as c FROM words w
          LEFT JOIN word_verses wv ON w.id = wv.word_id
          WHERE wv.id IS NULL`
       ).get().c;
       check('No orphan words', orphanWords === 0, `Found ${orphanWords} words without verses`);

       // Check 6: Level word counts in range
       const badLevels = db.prepare(
         'SELECT id, word_count FROM levels WHERE word_count < 25 OR word_count > 50'
       ).all();
       check('Level word counts 25-50', badLevels.length === 0,
         `Levels out of range: ${badLevels.map(l => `${l.id}:${l.word_count}`).join(', ')}`);

       // Check 7: Cumulative coverage monotonically increasing
       const coverages = db.prepare('SELECT cumulative_coverage FROM levels ORDER BY id').all();
       let monotonic = true;
       for (let i = 1; i < coverages.length; i++) {
         if (coverages[i].cumulative_coverage <= coverages[i-1].cumulative_coverage) {
           monotonic = false;
           break;
         }
       }
       check('Coverage monotonically increasing', monotonic, 'Coverage not strictly increasing');
       check('Final coverage <= 1.0', coverages[coverages.length-1].cumulative_coverage <= 1.0,
         `Final coverage: ${coverages[coverages.length-1].cumulative_coverage}`);

       // Check 8: Gaps report exists
       check('gaps-report.json exists', fs.existsSync(GAPS_PATH), `${GAPS_PATH} not found`);
       if (fs.existsSync(GAPS_PATH)) {
         const report = JSON.parse(fs.readFileSync(GAPS_PATH, 'utf8'));
         check('Gaps report has structure', report.totalWords > 0 && Array.isArray(report.gaps),
           'Invalid gaps report structure');
       }

       db.close();

       console.log(`\nValidation complete: ${errors} errors`);
       process.exit(errors > 0 ? 1 : 0);
       ```
